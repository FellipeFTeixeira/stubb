## Bloqueios e dúvidas

## Descobertas para o napkin

- [WC] TypeORM `.orIgnore()` gera `ON CONFLICT DO NOTHING` sem alvo, que ignora qualquer violação de unique (anula a última defesa); para sincronizar filhos, calcular o diff de IDs e inserir só os novos. Bash com muitos heredocs falha por inteiro de novo (heredoc com aspas simples dentro): usar Write ou script Node. `migration:generate` usa o nome sem timestamp e prefixa o próprio (`<ts>-CatalogSchema.ts`); depois rodar prettier no arquivo gerado (usa aspas duplas). Teste de relógio: `Clock` com estado mutável (`clockState.now`) no override permite avançar o tempo sem recriar o app.

- [UP] No Zod 4, para ligar um formulário de texto ao schema do contrato use `z.object({...strings}).transform((v): unknown => ...).pipe(schemaDoContrato)`: o `unknown` evita o erro de tipo entre `string` e enum, e os `issues` saem com o `path` do campo (RHF aceita `rows.0.label`). Para campo com conversão (preço, data) use `z.string().transform((t, ctx) => { ctx.issues.push({ code: 'custom', message, input: t }); return z.NEVER }).pipe(campoDoContrato)` por propriedade, assim o erro cai no campo certo. `userEvent.type` não serve para `datetime-local` no jsdom: usar `fireEvent.change(campo, { target: { value: '2026-12-10T20:00' } })`. Heredoc com `$`/crase/aspas no Bash tool falhou de novo ("unexpected EOF"): usar Write.

- [US] `@typescript-eslint/no-base-to-string` reprova `String(input)` quando `input` é `string | URL | Request`; tratar `Request` (`.url`) e `URL` (`.href`) explicitamente no fetch falso. `pnpm exec prettier --write` reescreve arquivos recém-criados (o harness avisa que mudaram no disco). Bash com muitos heredocs falha por inteiro (napkin já tem): usar Write.

- [C] `Date.UTC(2026, 12, 40, ...)` rola o calendário em vez de falhar; validar data inexistente exige comparar os campos de volta. No Zod 4, `z.discriminatedUnion` aceita objeto com `.superRefine` (a refinação não troca o tipo), e `z.url({ protocol: /^https$/ })` rejeita `http://`.
